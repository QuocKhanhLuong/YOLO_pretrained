## External Signals (Researcher)

- PostgreSQL plain SQL dumps can be parsed from `COPY` blocks for this targeted
  workflow, but the parser must stream data and preserve COPY escaping/null
  semantics.
- Treat the DB backup as the source of truth for `data_v2.0`: labels from
  `public.annotations.yolo_text`, images from `public.frames.image_path`, and no
  reuse of old `output/` or raw `dataset_raw` label templates.
- Class mapping is the highest-risk data-quality issue; prefer ordered
  `classes.txt` when present and record the class source in the report.
- Video-frame datasets need video-level splitting to reduce leakage between
  train, validation, and test splits.
- DVC/rclone transfer should remain manual and documented; scripts should not
  run remote transfer or training automatically.

## Internal Health (Architect)

- Existing prepared datasets use `images/{train,val,test}`,
  `labels/{train,val,test}`, `classes.txt`, `manifest.csv`, `data.yaml`,
  `dataset_report.md`, and dataset-local `GUIDE.md`; `data_v2.0` should keep
  that contract.
- `create_yolo_yaml.py` and `check_yolo_dataset.py` already define the local
  validation workflow and should be reused after the build.
- `scripts/train_yolo.py` already supports the requested augmentation and
  fine-tuning arguments: `mosaic`, `scale`, `translate`, HSV controls,
  `degrees`, flips, `freeze`, `weight_decay`, and `warmup_epochs`.
- `data/versions/.gitignore` needs a `data_v2.0` entry so DVC owns the prepared
  dataset directory.
