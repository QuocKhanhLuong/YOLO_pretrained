## External Signals (Researcher)

- UAV and small-object YOLO EDA should prioritize box-size distribution, pixel box size, per-class counts, empty or near-empty images, image resolution, objects-per-image density, and label sanity checks.
- High `mAP50` with much lower `mAP50-95` usually means coarse detections are present but localization is weak; tiny boxes and inconsistent box tightness make stricter IoU metrics drop quickly.
- Drone imagery commonly fails on recall because small, dense, blurry, or low-contrast objects are easy to miss.
- Label quality is a model-quality dependency: missing objects, duplicate boxes, class mismatches, out-of-bounds boxes, zero-area boxes, and extreme aspect ratios can make training and validation metrics unreliable.
- Practical small-object paths are larger `imgsz`, tiling/slicing, class- or size-aware sampling, and annotation cleanup before more model tuning.

## Internal Health (Architect)

- Existing `scripts/eda_yolo_dataset.py` already writes `eda_report.md`, `eda_summary.json`, `image_summary.csv`, `box_summary.csv`, and plots. The implementation should preserve this output contract while expanding diagnostics.
- The repo intentionally keeps dependencies small: standard library, matplotlib, Pillow, and optional cv2 are enough. Avoid pandas, numpy, and PyYAML for this task.
- Current EDA lacked pixel bbox stats, split/class imbalance interpretation, relative Markdown plot links, duplicate-stem hygiene, and metric-oriented report text.
- Dataset parsing logic is duplicated across scripts, but a narrow standalone extension is lower risk than refactoring shared helpers while no broad test suite exists.
- `docs/TRAINING_GUIDE.md` should stay compact and point users to the EDA command rather than duplicating the full report structure.
